# Bubo architecture

Bubo targets .NET 10 and uses inward dependencies: CLI -> infrastructure/application -> domain. Shared AssetProduction contains workspace guards, hashing, atomic persistence, locking, audit and bounded native process ownership. The Bubo.Host library validates the versioned caller context without depending on any workflow or Hephaera installation.

The three extracted workflow trees retain their original domain, application, infrastructure and executable fixture projects. Their current namespaces and exported motion/action identifiers use Hephaera. Execution API 2 declares this deliberate identity break; immutable API-1 imports and approvals remain historical rather than silently converted. Audited execution resources live under resources/, separate from host policy.

The media tree follows the same inward layering. Its domain defines versioned requests/capabilities, application admits host policy and budgets, and infrastructure verifies complete pinned installations and launches fixed native/Python workers. Provisioning is an explicitly authorized separate operation. The CLI composes the shared GPU guardian for reconstruction/media; it owns a global cooperative lease until native descendants retire. Media has no Hephaera dependency, game engine selector or asset-promotion authority.

The bubo entrypoint composes validated host context, constrained workspace/process ports and workflow services. It never interprets host instruction documents or calls an engine selector. References point to exact local files and hashes; native tools are explicitly selected existing executables. These cooperative guards and owned-process controls are not an OS sandbox.

Runtime resources, scripts, model/tool selections, ancestry and exported packages are hash-bound. Extracted workflow ancestry remains in provenance/hephaera-extraction.json; direct media additions have their own pinned catalog and installation identities. Setup/build and production execution are separate; production invokes an explicitly built CLI and downloads nothing.

No web framework, Docker, agent/provider coding loop, automatic human approval or automatic asset promotion is part of this runtime. Execution fixtures label simulated inference/approval separately from actual Blender and presentation evidence.

## Floor-plan design

The floor-plan-to-model tree adds pure typed dimensional contracts and bounded geometric validation in Domain, architectural compilation and renderer ports in Application, and strict serialization, deterministic SVG drawing and immutable workspace lifecycle in Infrastructure. The CLI supplies existing validated host context and exact build/style identities. Legacy v1 plans remain immutable design-only inputs. Explicit v2 profiles add approved construction dimensions and material roles; Domain compiles bounded deterministic closed triangle solids and measured routes/door envelopes. Infrastructure admits the exact complete design approval, verified fixed Blender bundle/tool identity and finite owned-job resources before authoring editable source. Static/dynamic collision representations and semantic floor/pivot hierarchy remain separate. Authoring reports are measured receipts; a separate fixed CPU QA renderer independently loads the source without resaving it. Portable export seals source, approved drawings, dimensional semantics and separate visual/collision GLBs. Fixed producers and fresh-process importers compare actual oriented world triangles, materials and hierarchy to native geometry. The host-facing lifecycle admits exact tools, cumulative process/file/work budgets, immutable latest-attempt history and separate independent/human decisions. A fixed renderer clips imported delivered geometry for complete architectural review views; verification and decisions remain outside the sealed payload to avoid hash cycles. Engine behavior remains outside the portable design/export boundary.

## Schematic design and mechanical readiness

The schematic-to-model tree follows the same inward layers. Domain owns typed assembly designs, dimensional/connectivity validation, frames and finite profiles. Application compiles complete schematic packages, rigid mechanisms and owned flexible-ring programs, and verifies actual triangle interference and sampled clearance. Infrastructure renders the dimensioned drawings and BOM, constructs independent part definitions through fixed audited Blender scripts, and coordinates immutable assembly and diagnostic attempts under one asset lock.

Every physical occurrence retains its own identity and transform. Flexible occurrences own real skins and rigs; shared rigid prototypes never merge physical nodes. Independent reopening measures the saved scene, and native verification compares actual geometry, pivots, materials, skinning and every declared diagnostic pose. Exact geometry proof reuse is operation-local, with one cumulative work ledger. Reports distinguish measured surface minima from certified conservative separation bounds. Finite samples do not certify continuous collision, manufacturing or finished animation.

Explicit v2 whole-design approval covers mechanism, contact, deformation and sampling choices before assembly. V1 remains design and independent parts only. Current source, approvals, tools, resource bytes and part/assembly/proof ancestry are revalidated at each boundary; failed latest attempts remain retained and invalidate dependents. Portable export, downstream motion admission, human model acceptance and engine promotion are separate boundaries.
