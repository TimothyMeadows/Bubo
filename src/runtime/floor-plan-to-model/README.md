# Floor-plan architecture runtime

Domain owns typed metre-based design, explicit construction profiles, bounded geometric validation/compilation and measured door/route evidence. Application owns preview compilation and renderer admission. Infrastructure owns strict JSON, complete SVG packages, immutable whole-building review, fixed audited Blender authoring and fresh output verification. CLI supplies the existing validated host context and native process owner; no host instruction documents are read.

V1 stays design-only. V2 construction requires every exact detail dimension/material role in approved source and the complete current drawing package, including construction-details.svg. Editable Blender source, visual/static-dynamic collision representations and floor/pivot semantics are staged together. GLB/export/re-import, human model acceptance, engine behavior and runtime promotion remain separate.

See resources/floor-plan-to-model/CONSTRUCTION.md and the fixed blender/README.md for conventions and execution limits. GeometryChecks reports construction-stage work; prerequisite validation/freshness stages independently enforce the same finite source cap and share cancellation/deadline. Native memory enforcement currently requires supported 64-bit Windows owned jobs; no unbounded fallback is available. The test executable's process/reviewer fixtures are explicitly synthetic, while actual Blender source and CPU render checks have separate receipts.
